# api.rst-game.com 在线探测报告 (2026-08-26)

> 方法: 结构化错误探测 (probe_live_api.py) — 用错误响应反推协议
> 与静态逆向互补: 原站认证中间件仍全功能运行

## 错误码分类学 (权威)

| 情形 | HTTP | JSON code | 说明 |
|---|---|---|---|
| 未知路由 (任意方法) | **200** | 404 | `{"code":404,"message":"サービス終了しました"}` |
| 真实端点 + 无 token | 200 | 400 | 业务层拒绝 (带完整9年感谢停服文案) |
| 真实端点 + 任意 token (表单/`TOKEN`头) | 200 | **700** | **认证层先于业务层运行**, token 无效 |

- 全部 104 端点均存活为真实路由 (200+400/700, 无一路由级 404)
- 方法不校验: GET/OPTIONS/POST 同样响应
- Body 不解析: JSON/二进制垃圾同样走 code 路径
- `Server: nginx`, `Content-Type: application/json; charset=UTF-8`
- code=700 的客户端语义 (字符串池): `トークンが存在しない。ログインしなおしかな。` → 触发重新登录

## 私服对齐情况 (rst_srv)

- ✅ 全响应 HTTP 200, 错误在 JSON code (NoRoute/NoMethod → code 404)
- ✅ code 700 = token 无效 (requireAuth 及全部 handler)
- ✅ TOKEN 头 + 表单 token 双通道
- ⚠️ 有意偏差: 无 token 时私服返回 700 (触发重登录), 原站是 400 停服文案
  (纪念服语义: 重登录自动建档, 优于弹"服务已结束")

## 探测局限

原站业务层已被停服逻辑短路, 无法观察成功响应结构 —— 响应字段仍以
RESPONSE_FIELDS.md (DTO 静态逆向) 为权威。请求侧字段名可继续用
"错误差异探测"补充, 但原站不校验参数 (任意 body 均 400), 已无可提取信息。
